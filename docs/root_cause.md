# Execution and policy root-cause record

Updated 21 September 2026. The investigation kept every change inside this repository. No system, driver, Conda, ROS, Isaac, CPU-isolation, or existing robot-workspace setting was changed.

| Symptom | Root cause | Evidence | Resolution |
| --- | --- | --- | --- |
| Isaac crashed during early task startup | USD/PhysX modules were imported before Kit's `SimulationApp` owned the process | crash occurred in the generic CLI path before environment construction | `isaac_train_entry.py` and `evaluate_isaac.py` construct `AppLauncher` before any Kit-dependent import |
| Kit tried remote services and its crash reporter attempted one upload after the early crash | Kit defaults enabled Hub reconnection and crash reporting | startup logs showed Hub retries; the initial crash created the only upload attempt | every final launcher disables crash reporting, old-dump upload, telemetry and privacy data, then enters a private user/network namespace; public asset fetch remains a separate explicit setup command |
| The default ground delayed offline startup | `GroundPlaneCfg` references an NVIDIA Nucleus asset | offline startup repeatedly waited for the remote asset | the scene uses an equivalent repo-local 200 m × 200 m kinematic collision cuboid |
| Most parallel robots silently fell below the scene | the repo-local floor was one global 20 m × 20 m cuboid, while 512 environments at 2.5 m spacing occupy an approximately 58 m-wide grid | the evidence-curriculum run immediately produced negative exponential heights and a large vertical-speed penalty; the grid/floor extent calculation identified which environments had no floor | enlarge the shared floor to 200 m × 200 m, enough for the configured 4,096-environment grid with margin; a numerical coverage test guards the relationship |
| A generic contact sensor resolved only the pelvis | the URDF importer preserved X2's nested rigid-body hierarchy, while the usual body expression assumed sibling link prims | runtime inspection found 32 articulated rigid bodies but one generic sensor body | the spawn callback enables contact reporting on every composed rigid body; one verified recursive PhysX view exposes all 32 ordered bodies |
| RSL-RL checkpoint load warned about obsolete observation groups | RSL-RL 5 renamed the actor/critic observation configuration | the first load used the compatibility fallback | train and evaluation pass the repository config through Isaac Lab's versioned migration helper |
| Early experiments did not start with the robot resting on the floor | the provisional 0.28 m pelvis height was chosen before evaluating the real collision meshes; the supine collision hull extends only 0.18030 m below the pelvis | full-URDF kinematic audit showed a nominal 99.7 mm floor gap, so every episode began with an avoidable fall and impact | final reset uses 0.190 m, zero root/joint speed and bounded root jitter; 20,000 collision-hull samples retain at least 6.3 mm clearance, and final PPO training restarts from scratch |
| Policy could not reach a straight-leg pose | hard limits were contracted to 90%, then actions were restricted to the central 85% again; asymmetric zero-endpoint knees were therefore limited to ≥0.282 rad flexion | official knee range is `[0,2.407]` rad and the collision audit gives a 0.675 m straight-leg pelvis height | use one 98% soft-limit contraction and the full soft action range, making ≥0.024 rad reachable while retaining a mechanical margin; final PPO training restarts from scratch |
| The first standing diagnostic appeared upside down | the diagnostic supplied a scalar-first identity literal to a scalar-last XYZW root-state writer | its first projected-gravity sample was `[0,0,+1]`; the installed API docstring specifies `(x,y,z,w)` | write identity as `[0,0,0,1]`; the final 100 Hz rerun began at 0.67460 m with projected gravity `[0.00368,0.00013,-0.99999]`, both feet loaded and no other-body contact |
| The training curriculum's nominal supine/standing poses were reversed | `InitialStateCfg` in the installed Isaac Lab 3.0 beta also uses scalar-last XYZW, but the base reset was encoded as scalar-first WXYZ; the resulting -180°/Y interpretation put X2 chest-down, and the curriculum's +90° pitch produced an inverted stand | the 64-environment live probe measured `g_b,z=+0.99996` for every nominal standing reset and zero standing feet contacts | encode -90°/Y as `XYZW=(0,-0.7071,0,0.7071)`, add a signed upright reward, and require live probes to see supine forward-axis Z near +1 and standing `g_b,z` near -1 before starting final PPO |
| The first corrected curriculum run fell back to reset-level reward as standing starts disappeared | the RSS table's 200 N is G1-specific; the initial X2 implementation copied it literally and applied it even while supine, while HoST's official cross-robot guidance says about 60% of robot weight and only after the trunk is near vertical | at iteration 368, mean reward was 1.76 and standing reward 0.015; the pinned X2 mass makes 60% weight 247.015 N | stop the run, scale the force from official URDF mass, gate it at `-g_b,z≥0.80`, add a numerical test, and restart final PPO from scratch |
| The first observation after later episode resets sometimes carried the preceding orientation | the installed Isaac Lab 3.0 beta PhysX root-pose writer invalidates root-pose buffers but not its same-timestamp `projected_gravity_b` derived buffer; `sim.forward()` does not advance the timestamp | before the workaround, repeated seeds produced reset Z-gravity components from `-0.826` to `+0.094` despite only ±0.005 rad roll/pitch jitter; source inspection identified the missing invalidation | the task-local reset wrapper invalidates gravity, heading and root-frame velocity buffers after every pose write; the five-seed live probe now gives identical data/observation vectors, zero speed and `|g_b,z|≤0.0047`; final PPO restarts from scratch |
| A correct straight pose slowly tipped forward | a floating-base humanoid needs base-state feedback even while a fixed straight joint target is held and its static COM projection begins inside the two-foot support hull | the corrected 100 Hz live PhysX probe satisfied every strict stance predicate for 0.65 s before tilt and velocity limits were crossed; the complete 7.95 s trajectory is recorded | retain the physical fall and make 0.5 s sustained active balance part of PPO success instead of pinning the base or relaxing the predicate |
| The first 500-iteration policy became upright but did not stand | orientation and foot contact were easier dense targets than lifting the pelvis | five seeds reached upright scores 0.997–1.000, but maximum pelvis height was 0.285–0.539 m and non-foot support remained | a measured branch increased dense height shaping and delayed support restrictions |
| The height-only branch reached a consistent 0.538–0.540 m but was physically wrong | height reward was independent of orientation, so PPO discovered an inverted bridge supported by the back or arms | final projected-gravity Z was positive in all five evaluations; upright score never exceeded 0.293 and other-body force reached 154–532 N | the branch is retained and labelled discarded; the final reward multiplies height and foot rewards by a positive upright gate and adds a signed upright target |
| The first orientation-gated branch preserved orientation but showed little rise | single-stage exploration had to discover a coordinated contact transition while also absorbing the incorrect 0.28 m reset impact inherited from its base checkpoint | training logs show high upright reward, near-zero inversion penalty, and near-zero height/foot terms | classify this as a diagnostic branch, fix the reset, and add the measured nine-pose recovery curriculum used by the final run |
| Relative actions were stronger than the documented equation | the target `q_current+βa` was recomputed at every 100 Hz physics substep, so one 20 Hz decision accumulated five times | source and live I/O audit showed the manager calls `apply_actions()` at each decimation substep | compute and clamp the target once in `process_actions()` and hold it for all five physics steps |
| The actor became numerically saturated | hard clipping made raw action 1 and 14 physically identical, while entropy rewarded a wider Gaussian; 87.2% of deterministic outputs exceeded ±1 | checkpoint audit found finite weights but raw actions as large as ±14 and saturated joint targets | replace the hard action clip with `tanh`, add raw action magnitude/rate penalties and set the entropy coefficient to zero; the selected actor's standard deviation is 0.0903–0.1024 and target limits remain valid |
| Foot-only contact observation aliased physically different recovery states | supine, elbow-supported and pelvis-supported configurations could share root/joint observations while the policy could observe only two foot bits | evaluation showed hundreds of newtons on unobserved supporting bodies | expose an ordered 32-body binary contact vector and retain exact-force contacts for reward and strict evaluation |
| Raw head height and positive vertical velocity increased while the pelvis stayed down | the first reward paid for torso rotation and upward bounces independently of upright pelvis rise | TensorBoard ended with high head-height and height-increase terms while all post-standing terms were zero | remove both exploitable terms and use linear normalized pelvis height multiplied by a squared positive-upright gate |
| Whole-body support appeared valid when it was actually a self-collision | `net_forces_w_history` sums every collision partner, including X2 self-collision pairs | pelvis and hip forces were exactly paired even without floor contact; the filtered partner matrix separated `/World/ground` | configure one ground filter and use `force_matrix_w_history` for every contact reward, observation and success check; exact sensor order and foot IDs 6/12 are audited |
| Generic RSL-RL export failed for the RMA actor | the exporter bypassed `get_latent` and fed 1,148 values directly into the actor's 118-input MLP | ONNX tracing reported a `1148 x 118` reduction mismatch | export an explicit tensor-only wrapper containing the trained normalizer, 10-step history encoder and MLP; the reloaded TorchScript output matches the source graph with zero measured error |
| The selected HumanUP checkpoint scored 0/5 from the floor despite approaching standing from `reference_2` | its saved final training configuration has `reference_min_stage=reference_max_stage=2`, so the actor never trained the lower bridge-to-supine transition in that phase | reference-2 audit reaches 0.5972 m and 0.25 s strict stance; five true-supine seeds never exceed 0.1905 m | retain the honest 0/5 result and continue one adjacent stage at a time; do not infer ground recovery from a reference-start rollout |
| Mixing stages 2–4 did not solve the new stages | PPO continued collecting exact-stance reward from the already solved easy stage while stages 3/4 fell before rising | a 7.2 M-transition follow-up still capped at initial 0.3944/0.3145 m on reference 3/4 | focus the next run on one new adjacent stage and require its deterministic audit to pass before unlocking the next stage |
| Another 21.6 M transitions on stage 3 still did not solve it | the actor optimized the dense terms available below the 0.58 m completion gate but never entered the final-state reward basin | normalizer count reached 97.704 M, exact-stance reward stayed zero, and deterministic peak changed from 0.4210 m to 0.4145 m | reject the longer checkpoint; obtain a dynamically valid transition with HumanUP motion extraction/retargeting or a teacher/student discovery stage before more PPO refinement |

All real-X2 runs use `cuda:0` with 3,000 parallel environments. HRS launchers set nice level 15 and CPU affinity `<HOST_CPUSET>`. ROS and Isaac remain separate processes and exchange only newline-delimited JSON through `/tmp/hrs_x2_recovery.sock`, whose mode is `0600`.
